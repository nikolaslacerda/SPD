# Quickstart: Benchmark de Modelos LLM

**Spec**: [spec.md](./spec.md) | **Data model**: [data-model.md](./data-model.md)

Manual, end-to-end validation guide for this feature once implemented. No automated test suite
is described here — see `tasks.md` (generated by `/speckit-tasks`) for the unit test tasks
required by constitution Principle VI.

## Prerequisites

- Node dependencies installed: `npm install` (repository root)
- A Chromium-based browser with WebGPU enabled (same requirement as the existing chat feature)
- A small sample PDF with a few paragraphs of text (any short document works, e.g. 1–3 pages)

## Setup

```bash
npm start
```

Open the app in the browser, and navigate to the new **Benchmark** link in the top-level nav
(added to `app.html`) — this loads the lazy `benchmark` route.

## Scenario 1 — Configure and run a minimal benchmark (User Story 1, P1)

1. On the Benchmark page, select **one** LLM model from the list.
2. Leave chunk size and max vector store chunks at their defaults.
3. Upload the sample PDF as the input file.
4. Confirm the embedding model field shows the default embedding model.
5. Set the similarity threshold to, e.g., `70`.
6. Add **one** test question: a question clearly answerable from the sample PDF's content, and
   an expected answer summarizing the correct answer in your own words.
7. Click **Run**.

**Expected outcome**:
- The Run button is disabled/blocked before step 6 is complete (missing required fields) — try
  clicking Run with the question list empty first, and confirm a validation message appears and
  no run starts (FR-008).
- Once started, a progress indicator shows the PDF being ingested, then the selected model being
  loaded and the question being processed (FR-015).
- On completion, a results table shows exactly one row, with a generated answer, a similarity
  percentage, and a pass/fail verdict (FR-011, FR-012).

## Scenario 2 — Multiple models, guardrail and failure isolation (User Story 1 edge cases)

1. Repeat Scenario 1's configuration but select **two or more** models.
2. Add a second test question that is clearly unrelated to the PDF's content (to trigger the
   query guardrail).
3. Run the benchmark.

**Expected outcome**:
- Both models are tested against both questions; a failure or guardrail block for one model does
  not stop the other model from being tested (FR-016, SC-004).
- The row for the unrelated question shows a `blocked` status, not a similarity score
  (FR-013, spec Edge Cases).

## Scenario 3 — Run-size warning (FR-008a)

1. Add more than 20 test questions, or select more than 5 models (if enough models are
   available).

**Expected outcome**: a non-blocking warning appears; the **Run** button remains enabled and a
run can still be started.

## Scenario 4 — View per-model metrics (User Story 2, P2)

After Scenario 2 completes:

**Expected outcome**: a summary block shows, per model, the average similarity percentage, the
pass rate, and the average response time (FR-014). The best-performing model (by average
similarity) is identifiable at a glance without extra explanation (SC-005).

## Scenario 5 — Export results (User Story 3, P3)

1. Before running any benchmark, confirm the **Export** button is disabled (FR-017,
   acceptance scenario 2).
2. After Scenario 1 or 2 completes, click **Export**.

**Expected outcome**: a `.csv` file downloads within a few seconds, containing one row per
model/question result plus the per-model summary rows (SC-003).

## Scenario 6 — Chat is disabled while a benchmark runs (research.md #12)

1. Start a benchmark run (Scenario 1 or 2) with at least one model that takes a few seconds to
   load.
2. While the run is in progress (`phase = 'running'` or `'ingesting'`), navigate to the Chat/Home
   page.

**Expected outcome**: the chat's message input and send action are disabled, with a short notice
that a benchmark is running (e.g., "O assistente está ocupado executando um benchmark"). Once the
benchmark run completes, return to Chat/Home and confirm the input/send action are enabled again.

## Regression check — existing chat flow unaffected

Since this feature modifies shared services (`LlmClient.setModel`, `PdfParser.parseFile`,
`VectorStore.initialize`), verify the existing chat flow on the Home page still works exactly as
before:

1. Navigate to the Chat/Home page.
2. Upload a PDF, ask a question, confirm a streamed answer appears with citations as before.
3. Confirm chunk size and vector store behavior for chat are unchanged (both now use the same
   defaults as before the benchmark feature was added).
4. Run a benchmark (Scenario 1 or 2) with a model **different** from the one chat was using, then
   navigate back to Chat/Home and ask another question. Confirm chat is using its original model
   again (not left on whatever model the benchmark last loaded) — this exercises the
   snapshot/lock/restore behavior in research.md #12, since `LlmClient` is a singleton shared
   between chat and the benchmark.
5. Confirm the chat's knowledge base (documents uploaded before the benchmark run) is still
   intact and searchable after running a benchmark — this exercises the isolated `VectorStore`
   instance from research.md #11, since a bug there would mix or clear the chat's data.
